What broke, in order

Each fix uncovered the next problem. The order below is the order they actually appeared, not a curated list.

  1. 01
    LICENSE

    Genymotion's CLI didn't know it was licensed

    $ gmtool admin osimages
A license is required to use this feature
    Cause
    Genymotion Desktop showed an active Personal Use license, but gmtool runs its own license check and hadn't picked it up. Clearing its cache only triggered a rate limit.
    Fix
    Created the virtual device from the Genymotion Desktop GUI instead: a Galaxy S24 profile running Android 13 (API 33, x86_64).
  2. 02
    TIMEOUT

    Appium never got to say it was ready

    Error: Timeout: Appium did not start within expected time
    Cause
    Appium loads every installed driver at startup, not just the one a run needs. Loading uiautomator2 and xcuitest took 30 to 45 seconds on this machine; the WebdriverIO Appium service gives up after exactly 30.
    Fix
    Set appiumStartTimeout to 90000 in config/wdio.conf.ts.
  3. 03
    NETWORKING

    Appium was listening, the client still couldn't reach it

    WebDriverError: Request failed with error code ECONNREFUSED
when running "http://127.0.0.1:4723/session"
    Cause
    On this machine, Node resolves localhost to the IPv6 loopback address first. Appium bound to that address; the WebdriverIO client dials the IPv4 address by default. Two different sockets, same port number.
    Fix
    Set APPIUM_HOST to 127.0.0.1 in .env, so the server and the client agree on which loopback address to use.
  4. 04
    MISSING SDK

    The driver couldn't find adb

    WebDriverError: Neither ANDROID_HOME nor ANDROID_SDK_ROOT
environment variable was exported
    Cause
    No Android SDK had ever been installed on this machine. Genymotion ships its own copy of adb, but appium-adb reads the ANDROID_HOME environment variable, not the Windows PATH.
    Fix
    Pointed ANDROID_HOME at Genymotion's install folder as a first pass, since its tools/ directory happened to match one of appium-adb's search paths.
  5. 05
    ROOT CAUSE

    Genymotion's folder isn't an SDK

    Could not find 'aapt2.exe' in [...]
Could not find 'apksigner.jar' in [...]
    Cause
    Genymotion bundles adb and the older aapt, not the full Android build-tools. appium-adb needs aapt2 to read an APK's manifest and apksigner to check its signature before installing it. Setting appPackage and appActivity explicitly skipped the manifest read, but the signature check still needed apksigner.
    Fix
    Installed a real Android SDK (platform-tools plus build-tools 34.0.0) at C:\Android\Sdk, moved ANDROID_HOME there, and pointed Genymotion at that same SDK's adb, so only one adb version runs at a time.

From there, a session opened in about two seconds. FrontRow installed, launched, and rendered its real first screen: an event list with search, category filters, and one featured show.
